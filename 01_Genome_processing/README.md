# Genome processing

This workflow processes paired-end Illumina reads into coordinate-sorted, duplicate-filtered BAMs for variant discovery and depth analysis. Inputs are local FASTQ files; read acquisition is separate.

## Included input data

Run `unzip input_data.zip` in this directory to place `reference.fasta` beside the scripts. Keep the working configuration here; its `REFERENCE` setting uses this filename. Use the existing run-manifest example for the sequencing inputs. Raw FASTQ files and adapter sequences are supplied separately; reference indexes are generated by `01_prepare_reference.sh`.

## Configuration

Copy `config.example.sh` to `config.sh` and replace its placeholder paths. Copy `runs.example.tsv` and provide one row per paired-end sequencing run, using the exact tab-separated header. Paths in the configuration are relative to that configuration file; FASTQ paths are relative to the manifest. Absolute paths and paths containing spaces are supported. Reads must use Phred+33 quality scores. Tool versions and library preparation metadata should be recorded with each analysis.

The manifest contains `sample_id`, `run_id`, `library_id`, `flowcell`, `lane`, `read1`, `read2` and `trim_method`. Identifiers use letters, digits, dots, underscores or hyphens and begin with a letter or digit. Each run ID must be unique. `trim_method` is `trimmomatic` or `fastp`.

Use the same sample ID for runs from the same biological isolate. Use the same library ID only for runs derived from the same physical library preparation; independent library preparations require distinct library IDs. Read-group IDs retain the flowcell, lane and run ID, `SM` contains the sample ID, `LB` contains the library ID, and `PU` records the flowcell and lane. All runs from an isolate are combined before duplicate removal; Picard uses library labels to distinguish duplicate sets. The example manifest illustrates two sequencing runs from one library. Populate these fields from actual sequencing records.

## Execution

From this directory, run the numbered scripts in order:

```bash
bash 01_prepare_reference.sh config.sh
bash 02_trim_reads.sh config.sh
bash 03_read_qc.sh config.sh
bash 04_align_reads.sh config.sh
bash 05_remove_duplicates.sh config.sh
bash 06_measure_depth.sh config.sh
```

The reference must be a FASTA of the intended reference haplotype. `01_prepare_reference.sh` prepares BWA-MEM2 and SAMtools indexes beside it, retaining existing complete indexes. It also creates the SAM sequence dictionary required by the downstream variant-calling workflow using `samtools dict`. By default, `reference.fasta` produces `reference.dict`; an optional `REFERENCE_DICT` setting specifies another path. Existing non-empty dictionaries are retained, and empty dictionaries cause an error. Existing indexes and dictionaries must correspond to the supplied FASTA, and BWA-MEM2 indexes must match the installed tool version. Partial BWA-MEM2 indexes cause an error. Scripts process runs or isolates sequentially, with multithreading inside each tool; reserve sufficient memory for `SORT_MEMORY` per sorting thread and both commands in the alignment pipeline.

| Script | Analysis and outputs |
|---|---|
| `01_prepare_reference.sh` | BWA-MEM2 index, FASTA `.fai` index and SAM `.dict` sequence dictionary. |
| `02_trim_reads.sh` | Paired trimmed reads in `trimmed/<run>/`; Trimmomatic singletons are retained separately and are not aligned. |
| `03_read_qc.sh` | FastQC reports for the raw and paired trimmed reads, and a combined MultiQC report in `read_qc/summary/`. Run- and stage-specific names keep reports distinct. Inspect these reports before alignment. |
| `04_align_reads.sh` | BWA-MEM2 `mem` alignment, SAMtools coordinate sorting and `calmd -bAQr`; one BAM per run in `aligned/<run>/calmd.bam`. |
| `05_remove_duplicates.sh` | Isolate-level BAM, BAM index and duplicate metrics in `bam/<sample>/`. |
| `06_measure_depth.sh` | Mosdepth depth tracks, cumulative distributions and summary statistics in `depth/<sample>/`. |

Trimmomatic uses `ILLUMINACLIP:<adapter FASTA>:2:30:10 LEADING:3 TRAILING:3 SLIDINGWINDOW:4:15 MINLEN:31`. Fastp uses `-n 5 -q 15 -u 40 -l 31 --detect_adapter_for_pe -5 --cut_front_window_size 1 --cut_front_mean_quality 3 -r --cut_right_window_size 4 --cut_right_mean_quality 15 -g -x`. Set the appropriate adapter FASTA for Trimmomatic and review the choice of trimming method for each run.

`calmd -bAQr` recalculates alignment tags and applies BAQ adjustment to base qualities. Picard `MarkDuplicates` uses `REMOVE_DUPLICATES=true`; the final BAMs are indexed with SAMtools. Mosdepth retains its standard read-pair overlap handling and read-flag filtering, with the minimum mapping quality configured by `MOSDEPTH_MAPQ` (default 0). The summary files report per-chromosome and overall depth; no GC correction or CNV inference is performed here.

The intended software versions are Trimmomatic 0.39, fastp 0.24.0, FastQC 0.12.1, MultiQC 1.15, BWA-MEM2 2.2.1, SAMtools 1.17, Picard 3.0.0 and mosdepth 0.3.4. Executable names are configurable, including array-based `java -jar` commands for Picard and Trimmomatic. Bash 3.2 or later and standard Unix utilities are required.

Output directories are never overwritten. To repeat an analysis, choose a new output directory or deliberately manage the prior outputs first. Temporary files are removed if a step fails; successful run or isolate outputs remain available. The scripts do not determine whether multiple accessions are technical runs of one library, independent samples or redundant records; the manifest defines the intended grouping.
